18. MOTION SYSTEM
======================================================================

Approved direction:

    CINEMATIC EDITORIAL × REACTIVE TECHNOLOGY

Core rule:

    LARGE THINGS MOVE SLOWLY.
    SMALL THINGS RESPOND QUICKLY.

Motion should communicate hierarchy and continuity.

Do not animate simply to prove the site can animate.

Suggested timing families:

FAST       ~160ms
NORMAL     ~260ms
SLOW       ~500ms
CINEMATIC  ~800ms

Use a small consistent easing family.

Motion categories:

MICRO:
Buttons, links, controls.

INTERFACE:
Navigation states, fields, small reveals.

EDITORIAL:
Typography and image reveals.

ENVIRONMENTAL:
Day/night and major project transitions.

Potential effects:

- Elegant clipped typography reveals.
- Subtle hero image depth/crop movement.
- Environmental color/surface progression.
- Selected Work project-to-project transitions.
- Service-stage transformations.
- Very restrained pointer-reactive effects on capable desktop devices.
- Small arrow/line motion on CTAs.
- Environment-aware navigation.

AVOID:

- Splash screens.
- Fake loading percentages.
- "Enter Experience" gates.
- Scroll hijacking.
- Constant movement.
- Aggressive parallax.
- Autoplay audio.
- Giant custom cursors.
- Motion required to understand content.
- Excessive animation dependencies.

Prefer CSS-native animation/scroll capabilities for straightforward effects.

Add JavaScript animation libraries only where a meaningful interaction cannot
reasonably be implemented performantly and accessibly with modern CSS.

REDUCED MOTION:

The reduced-motion version must remain premium and complete.

Remove/reduce:
- Parallax.
- Large animated transformations.
- aggressive scroll-linked motion.
- elaborate travel effects.

Retain:
- Typography.
- Photography.
- composition.
- color/environment.
- usability.
- hierarchy.

[CODEX MAY TUNE]
Exact motion timings and easing after real-browser testing while preserving
the four timing categories and approved restrained character.

21. ACCESSIBILITY
======================================================================

Target:
WCAG 2.2 AA.

Accessibility is part of the design, not a final plugin/checklist.

Requirements include:

- Semantic HTML.
- Correct heading hierarchy.
- Header/nav/main/section/article/footer landmarks.
- Real links for navigation.
- Real buttons for actions.
- Real form controls.
- Keyboard operation.
- Visible branded focus states.
- Skip-to-main-content link.
- Color contrast.
- Meaningful alternative text.
- Form labels.
- Error identification and messaging.
- Accessible status updates.
- Reduced-motion support.
- Touch target sizing.
- Zoom/reflow compatibility.
- No hover-only information.
- Appropriate ARIA only where native semantics are insufficient.
- Accessible mobile navigation.
- Media accessibility.

Do not remove focus outlines simply for aesthetics.

Do not use color alone to communicate meaning.

22. PERFORMANCE
======================================================================

The site should feel advanced because it performs well.

Target strong Core Web Vitals.

Working targets on representative production pages/devices:

LCP ≤ 2.5s
INP ≤ 200ms
CLS ≤ 0.1

Prioritize:

- Responsive media.
- Efficient image formats.
- Font discipline.
- Minimal unnecessary JavaScript.
- Server rendering/static generation where appropriate.
- Code splitting.
- Deferred noncritical work.
- Efficient animations.
- Avoiding unnecessary third-party scripts.
- Avoiding enormous background videos.

Performance outranks a decorative animation.
